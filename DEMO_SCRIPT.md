# Видео работодателю: 2–4 минуты

Это инструкция записи, не утверждение, что live demo уже выполнено. Без API-ключа и успешного
реального прогона нельзя выдавать test provider за самостоятельные решения LLM.

## Подготовка

1. Добавьте ключ в `.env`; не показывайте этот файл в записи.
2. Запустите `python -m pytest -q` и live test из README.
3. Используйте новый отдельный профиль для чистого TodoMVC, без личных аккаунтов.
4. В учебной демонстрации допустим `SAFETY_MODE=balanced`; обозначьте этот выбор.
   В `conservative` оставьте реальные запросы `YES` в кадре.
5. Расположите Chromium и терминал рядом. Не меняйте скорость видео без подписи.

PowerShell из корня; переменные действуют только на эту сессию:

```powershell
$env:PROFILE_DIR=".browser-profile/video-demo"
$env:SAFETY_MODE="balanced"
$env:RECENT_HISTORY="3"
.\.venv\Scripts\python.exe -m browser_agent
```

Если профиль уже использовался, выберите новый суффикс, например `video-demo-2`,
а не удаляйте пользовательские данные ради чистой картинки.

## 0:00–0:10 — цель и репозиторий

Покажите README и дерево файлов. Скажите: «Это DOM-first агент с универсальными tools.
Задача вводится текстом, решения принимает модель на каждом шаге».

## 0:10–0:25 — запуск

Покажите команду. Открывается Chromium; терминал спрашивает задачу. Не показывайте ключ.

## 0:25–0:40 — natural-language task

Введите:

> Открой https://demo.playwright.dev/todomvc/. Добавь три задачи: «Прочитать README»,
> «Запустить тесты», «Записать демонстрацию». Отметь «Прочитать README» выполненной.
> Покажи только активные задачи. Сообщи, какие две задачи остались и сколько их.

Можно заменить названия задач перед записью — это помогает показать отсутствие записанного
workflow. Не меняйте core ради сценария.

## 0:40–2:30 — автономные решения

В браузере видны переход, ввод, появление новых строк, отметка выполненной задачи и смена фильтра.
В терминале — отдельные `STEP`, `ACTION`, runtime IDs и `RESULT`. Реальное время зависит от API,
поэтому это ориентир, не обещание уложиться в точный тайминг.

На динамическом моменте скажите: «Строки возникли после ввода. Агент получает новый снимок
и выбирает элементы из него; их ID в предыдущем снимке ещё не существовали».

Когда `memory_compacted` станет больше нуля: «Старые шаги уже сокращены, исходная цель сохранена.
Это рабочее управление контекстом, а не неограниченный список сообщений».
Не утверждайте, что этот счётчик сам доказывает качество планирования.

## 2:30–3:10 — проверка и finish

Покажите две оставшиеся задачи и счётчик на странице, затем `VERIFIER accepted completion`
и `COMPLETED`. Сверьте итог с UI. Если модель ошиблась, не называйте запись успешной:
исправьте общую причину и запишите новый настоящий прогон.

Фраза: «Перед итогом отдельный вызов проверяет свежие данные страницы. Это снижает риск
преждевременного finish, но модель всё равно может ошибаться».

## 3:10–3:30 — честные ограничения

«Есть подтверждения чувствительных действий, лимиты и восстановление. Canvas/CAPTCHA
автоматически не решаются. В core нет названий этого сайта или селекторов его приложения».
Не показывайте весь код в видео.

## Вторая задача, вне короткого ролика

Запустите новый goal из README на Books to Scrape: Travel, первые два товара, полные названия,
цены, сравнение без покупки. Зафиксируйте результат, шаги и реальные трудности в TEST_REPORT.
Этот другой UI лучше проверяет перенос навыка, чем повтор TodoMVC с другим названием задачи.

## Если что-то пошло не так

- Запрос пользователя: ответьте в терминале; для CAPTCHA действуйте вручную в Chromium.
- Отказ API: проверьте ключ, доступ модели и billing локально; не показывайте секреты.
- `stopped`/отклонение verifier: это безопасное завершение, не успешное выполнение цели.
- `--check` доказывает только запуск браузера. `tests/test_public.py` — только primitives.
- Не монтируйте тестовый provider и live API в один ролик так, будто это один автономный запуск.
